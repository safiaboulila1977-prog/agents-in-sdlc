GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ツール呼び出しやファイル編集をリアルタイムで確認できます。差分を確認して個別の変更を採用または取り消し、フォローアップのプロンプトでエディターを離れずに作業を調整できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントへ指示し、ハイコントラストモードに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson] で使用したアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいとのことです。新たに会話を始めるのではなく、既存のセッションに指示して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調べているファイル、実行するコマンド、提案する編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
    - **Keep** を選択すると変更を採用します。
    - **Undo** を選択すると変更を取り消し、エージェントにもう一度作業させます。
4. チャット上部の **Files changed** の表示を開いて、このセッション中にエージェントが変更した作業セット全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装するまで待ちます。最後に、行った変更の概要が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも追加します。同じチャットセッションを続けるため、エージェントは直前の作業、編集したコンポーネント、スタイルの方針、local storage を使った設定の保存方法などのコンテキストを保持しています。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはすでに行った変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。差分ごとに **Keep** または **Undo** を使います。
4. エージェントの進め方が期待と異なる場合 (たとえば、切り替え UI を意図しない形にリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確なフォローアップを送信します。

> [!TIP]
> 実行中のセッションへの追加指示は、新しいセッションを始めるよりも早く作業を進められます。「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込む」「両方の切り替えにキーボードショートカットを追加する」など、調整、修正、範囲の拡張を依頼できます。

## 作業セットをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して方向付けました。各ファイルの編集を確認して採用または取り消し、コンテキストを保持したままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- フォローアッププロンプトを使って、進行中のセッションを方向付ける。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが作成した変更をレビューします。
